# Архитектура каталога

Шаблоны расположены в `src`. Профили наследуются по цепочкам `base → net → net-consoleapp|net-webapp|net-desktopapp` и `base → iac-base → ansible|salt`; `python` и `unity` наследуются непосредственно от `base`. Overlay, fragments и удаления дочернего профиля применяются после родителя.

PowerShell используется на Windows, Bash — на Linux и macOS; оба генератора находятся в `make`. Каждый сначала собирает, преобразует и валидирует дерево во внутреннем temporary-каталоге, затем однократно публикует его в пустое назначение без переименований и перезаписи публичных файлов. Schema v2 manifest’ов содержит `pathRequirements`: `src`, `make`, `tests` и `tools` обязательны, а `docs` и `build` опциональны. Файлы наследуют статус ближайшего размеченного каталога; точное file-правило может его переопределить. .NET, Python и Unity имеют симметричные src/tests-компоненты; IaC, Ansible и Salt сохраняют пустой `tests/.gitkeep`. `build/<component>` обязателен только у .NET, Python и Unity. Это правило относится к создаваемым репозиториям: в самом каталоге тестов есть единственный файл `tests/test_templates.py`, который проверяет все profiles и не зеркалит `src`. `verify` проверяет контракт шаблона, `build` собирает проект, а `tests` запускает проектные тесты и линтеры. Контейнерный Python-тест сравнивает результаты обоих генераторов, включая host bind mount.
