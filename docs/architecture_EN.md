# Catalog Architecture

Templates are stored in `src`. Profiles inherit through `base → net → net-consoleapp|net-webapp|net-desktopapp` and `base → iac-base → ansible|salt`; `python` and `unity` inherit directly from `base`. A child profile's overlay, fragments, and removals are applied after its parent.

PowerShell is used on Windows and Bash on Linux and macOS; both generators are in `make`. Each first composes, transforms, and validates the tree in a private temporary directory, then publishes it once to an empty destination without renaming or overwriting public files. Schema v2 manifests contain `pathRequirements`: `src`, `make`, `tests`, and `tools` are required, while `docs` and `build` are optional. Files inherit the status of their nearest marked directory, and an exact file rule can override it. .NET, Python, and Unity have matching src/tests components; IaC, Ansible, and Salt retain an empty `tests/.gitkeep`. `build/<component>` is required only for .NET, Python, and Unity. This rule applies to generated repositories: the catalog itself has one `tests/test_templates.py` file that validates every profile and does not mirror `src`. `verify` checks the template contract, `build` builds the project, and `tests` runs project tests and linters. The containerized Python test compares both generator outputs, including a host bind mount.
