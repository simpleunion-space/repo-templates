# Repository Guidelines

Этот репозиторий поддерживает шаблоны, а не готовый продукт. Изменения в base-template должны оставаться технологически нейтральными; стековые настройки добавляются только в соответствующий профиль.

Перед правками прочитайте корневой README, манифест профиля и связанный двуязычный документ. Изменяйте русскую и английскую версии в одной задаче. Не добавляйте вложенные Git-репозитории, реальные секреты, production-конфигурации или поставочные артефакты.

После изменения генератора, манифестов, base или profile overlays запускайте `docker compose -f tools/docker/verify.yaml run --rm template-verify` и `docker compose -f tools/docker/tests.yaml run --rm template-tests`. На Windows, Linux и macOS проверки запускаются только через Docker Compose; `tools/scripts/*.sh` вызываются контейнерами. Используйте генераторы из `make/New-RepositoryFromTemplate.ps1` или `make/New-RepositoryFromTemplate.sh` только с временным пустым каталогом при проверке генерации. Compose создаёт только локальный test image/cache; скрипты каталога не выполняют git init, deploy, apply или операции с инфраструктурой.

`pathRequirements` в manifest — источник истины для обязательных и опциональных путей. Для обязательных `src`, `make`, `tests` и `tools` сохраняйте все требуемые файлы; `docs` и `build` не создавайте без настоящего содержимого. Исключение: .NET, Python и Unity объявляют обязательные component-каталоги в `build`.

`verify.sh` проверяет контракт шаблона, `build.sh` создаёт артефакты проекта только для поддерживающих сборку профилей, а `tests.sh` запускает тесты и линтеры проекта. IaC, Ansible и Salt не получают тестовых component-каталогов.

Сначала сохраняйте существующие изменения рабочего дерева. Явное подтверждение требуется для удаления данных, переписывания Git-истории, публикации, deploy/apply, миграций и любых операций с внешней инфраструктурой.
