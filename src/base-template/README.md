## Структура

- src — обязательные исходные материалы или код проекта, сгруппированные по компонентам.
- tests — обязательные тесты проекта; профиль может оставить каталог пустым с `.gitkeep`.
- make — обязательный фасад Docker Compose для Linux и macOS.
- tools/scripts — обязательные проверочные скрипты.
- tools/docker — обязательные Docker Compose точки входа.
- docs — опциональная расширенная документация: каталог существует только при наличии настоящих документов.
- build — опциональные результаты сборки: каталог не создаётся без фактических артефактов, если профиль не объявляет его обязательным.

Статусы путей объявлены в `.template/template.json` через `pathRequirements`. Файл наследует статус ближайшего размеченного каталога, а точное file-правило может его переопределить. `.gitkeep` сохраняет обязательную пустую структуру, но не делает опциональный каталог непустым.

## Работа с проектом

Используйте `make -f make/Makefile verify`, `build`, `tests`, `up` и `down` либо эквивалентные Compose-команды из docs/development.md. `verify` проверяет контракт сгенерированного шаблона, `build` создаёт артефакты проекта, а `tests` запускает проектные тесты и линтеры. CI должен вызывать те же проверки, что и локальная разработка.

## Конфигурация и секреты

Версионируйте только безопасные значения по умолчанию и файлы-примеры. Секреты передавайте через переменные окружения, secret store или защищённые CI variables.

## Документация

Смотрите индекс документации в docs/README.md, правила в CODESTYLE.md и инструкции в AGENTS.md. Создавайте MODEL.md и ARCHITECTURE.md только при наличии устойчивой доменной модели или многокомпонентной архитектуры.
