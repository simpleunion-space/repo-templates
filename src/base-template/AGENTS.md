# Repository Guidelines

Сначала прочитайте README, development-документ и состояние Git. Сохраняйте незакоммиченные изменения пользователя и не отменяйте их без явного запроса.

Выполняйте read-only анализ и локальные проверки по умолчанию. Для каждой добавленной или изменённой русской Markdown-документации обновляйте английскую пару в той же задаче.

Перед явным подтверждением не выполняйте deploy или apply, миграции, удаление данных, очистку shared-ресурсов, публикацию артефактов, перезапись истории Git и изменения внешней инфраструктуры. Не добавляйте реальные секреты в Git; используйте только безопасные примеры конфигурации.

Документируйте фактические команды проекта в docs/development.md. На Windows, Linux и macOS запускайте проверки только через Compose-файлы или `make -f make/Makefile <цель>` как фасад к ним; `tools/scripts/*.sh` — внутренние entrypoint-ы контейнеров. Не объявляйте разрешёнными команды, которые не существуют в проекте или требуют внешних побочных эффектов.

Сохраняйте обязательные `src`, `make`, `tests` и `tools`. `docs` и `build` являются опциональными: не добавляйте их без настоящего содержимого, а требования профиля фиксируйте в `pathRequirements`.

`verify.sh` проверяет контракт шаблона, `build.sh` создаёт артефакты только когда это применимо, а `tests.sh` запускает тесты и линтеры проекта.
